# 平台国际化 i18n 后端骨架（S2）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立 myapp 的 pybabel 翻译工作流并交付 en catalog（zh 为源语言），前端 antd 组件 locale 跟随 `LOCALE` 环境变量切换。

**Architecture:** 后端以 `myapp/babel.cfg` + `scripts/i18n_{extract,update,compile}.sh` 三脚本构成提取/更新/编译流水线，产出 `myapp/translations/en/LC_MESSAGES/messages.{po,mo}`（zh 不建 catalog，缺失自动回退中文）；镜像构建期编译 .mo。前端无 i18n 框架、无模板注入路径（React 构建产物 index.html 为静态文件，不经 Jinja 渲染），因此 locale 经由既有 `/userinfo/api/current/userinfo` 接口下发，`index.tsx` 登录后拉取再渲染 `ConfigProvider`。

**Tech Stack:** Flask-Babel 4.0（基础镜像已装，本计划恢复显式依赖声明）/ Babel CLI（pybabel）/ antd 4.21 locale / pytest

**Spec:** `docs/superpowers/specs/2026-11-07-platform-i18n-design.md`

## Global Constraints

- 只交付 en catalog；**不创建 zh 目录**（flask-babel 默认回退源语言中文，spec §4.1/§5）。
- 提取关键字必须显式为 `-k __ -k _ -k lazy_gettext`（与现有代码 `from flask_babel import gettext as __, lazy_gettext as _` 用法一致，spec §4.1）。
- v1 翻译范围：home.py 菜单树 + view_team.py 表单（spec §2 目标 4）；`msgstr` 留空的条目回退中文，属预期行为。
- 前端不引入 react-i18next，不新增 locale 请求以外的接口改动（spec §3/§4.3）。
- 语言切换仅靠部署级 `LOCALE` 环境变量（config.py 已读：`BABEL_DEFAULT_LOCALE = os.getenv('LOCALE','zh')`），不做用户级切换 UI（spec §4.4）。
- 测试命令在仓库根目录：`python -m pytest tests/test_i18n.py -v`（tests/ 目录由 S4 计划 Task 1 创建；若执行本计划时 S4 尚未实施，先创建 `tests/` 目录与空 `__init__.py` 不需要——pytest 无需 `__init__.py`）。
- 测试不 boot Flask app（同 S4 计划「测试边界说明」：`SQLALCHEMY_DATABASE_URI` 空串导致本地无法创建 app），en 翻译断言走 `babel.support.Translations` 直接装载 .mo。
- Windows 下脚本经 git-bash 执行：`bash scripts/i18n_extract.sh`。
- 每个 Task 结束 commit，提交信息 `feat:` / `build:` / `test:` 前缀。

## 与 spec 的偏差说明（2 处，均已定案）

1. **spec §4.3「后端模板注入 window.SERVER_LOCALE」不可行**：React 前端（fab 模式）产物为 `static/appbuilder/frontend/index.html` 静态文件，由 FAB 直接 serve，不经任何 Jinja 模板渲染，无注入点。改为：`/userinfo/api/current/userinfo` GET 响应增加 `locale` 字段，`index.tsx` 在已有登录 cookie 判断后 fetch 该接口再渲染。该接口前端本就用于用户态，无新增请求面。
2. **spec §4.1「requirements-dev.txt 补 Babel」不适用**：仓库根无 requirements-dev.txt（gov-social-llm/ 下才有）。改为在 `install/docker/requirements.txt` 恢复被注释的 `Flask-Babel==4.0.0`（L21），pybabel CLI 随 Babel 包（Flask-Babel 依赖）可用。

- [ ] **Step 2: 创建三个脚本**

创建 `scripts/i18n_extract.sh`：

```bash
#!/usr/bin/env bash
# 提取 myapp 源码中 __()/_()/lazy_gettext 字符串到 pot 模板（仓库根执行）
set -e
pybabel extract -F myapp/babel.cfg -k __ -k _ -k lazy_gettext -o myapp/translations/messages.pot .
echo "extracted -> myapp/translations/messages.pot"
```

创建 `scripts/i18n_update.sh`：

```bash
#!/usr/bin/env bash
# 按 pot 更新各语言 po（保留已翻译条目，新增条目标记 fuzzy/空）（仓库根执行）
set -e
pybabel update -i myapp/translations/messages.pot -d myapp/translations
echo "updated po files -> myapp/translations"
```

创建 `scripts/i18n_compile.sh`：

```bash
#!/usr/bin/env bash
# 编译 po -> mo（仓库根执行）
set -e
pybabel compile -d myapp/translations
echo "compiled mo files -> myapp/translations"
```


Expected: 命令成功，`myapp/translations/messages.pot` 生成，`reading config file myapp/babel.cfg` 且提取出上千条 msgid（含 home.py 的菜单字符串）。

- [ ] **Step 2: 前端 index.tsx 跟随**

将 `myapp/frontend/src/index.tsx` 中 L6 的 import 与 L23-38 的渲染段改为：

```tsx
import zhCN from 'antd/lib/locale/zh_CN';
import enUS from 'antd/lib/locale/en_US';
```

```tsx
let isLogin = false
const userName = cookies.get('myapp_username')

if (!!userName) {
isLogin = true
} else {
  handleTips.gotoLogin()
}

const renderApp = (locale: any) => {
  ReactDOM.render(
    isLogin ?
<ConfigProvider locale={locale}>
      <BrowserRouter basename={process.env.REACT_APP_BASE_ROUTER || '/'}>
        <App />
      </BrowserRouter>
</ConfigProvider> : <></>,
    document.getElementById('root')
  );
}

if (isLogin) {
  fetch('/userinfo/api/current/userinfo', { credentials: 'same-origin' })
    .then(res => res.json())
    .then((res: any) => {
      renderApp(res?.locale === 'en' ? enUS : zhCN)
    })
    .catch(() => renderApp(zhCN))
} else {
  renderApp(zhCN)
}
```

要点：接口失败/字段缺失一律回退 `zhCN`（安全降级，与 spec §5 精神一致）；`ReactDOM.render` 只调用一次，杜绝双渲染。
